## 一、安全专家视角

### P0-1 降级通道全局禁用 TLS 证书校验（凭据可被截获）
- 位置：`app/src/main/python/engine.py:136` `"nocheckcertificate": True`
- 影响：内嵌 yt-dlp 是 X/IG 受限内容的**唯一带 Cookie 请求通道**（auth_token/ct0/sessionid 在请求头里）。证书校验关闭后，任何中间位置（恶意代理、公共 Wi-Fi、被污染的“优选代理”节点本身）都能明文拿到登录态 → 账号被完全接管。本项目核心卖点恰恰是“代理自动优选”，等于把凭据主动递给评分最高但不可信的节点。
- 修复：直接删除该选项；若为兼容个别 CDN 自签证书，改为按域名白名单（`nocheckcertificate` 无域粒度，可用 `--downloader-args` 或干脆保留默认校验，失败域单独记录）。

### P0-2 登录凭据明文存储 + allowBackup="true"
- 位置：`AndroidManifest.xml:15`（`android:allowBackup="true"`）；`Store.kt:163-170`（twAuthToken/twCt0/igCookie 明文 SharedPreferences）；`Store.kt:158-161`（clashImport 订阅原文，含节点服务器/密码）
- 影响：云备份（Google/厂商）与 adb backup 都会带走 `settings.xml` → 登录态、节点凭据一并出设备。设备不丢也能被同机 App（root/备份类）读走。
- 修复：① `allowBackup=false` 或加 `backup_rules.xml` 排除 `settings.xml`；② 凭据迁 EncryptedSharedPreferences（androidx.security-crypto）；③ clashImport 至少提示用户含敏感信息。

### P1-3 purgeEntries 用 startsWith 判“自有目录”，无分隔符
- 位置：`MediaFiles.kt:48-49` `!File(f).absolutePath.startsWith(base)`
- 影响：路径 `/storage/.../com.ep.donwnloader/files_evil/x.jpg` 会被误判为本 App 私有目录内 → **物理删除外部（Edqiu 生态）文件**，破坏共享引用契约。典型前缀边界 bug。
- 修复：`startsWith(base + File.separator)`；`ContentAccess.isForeign` 同样检查（它用 getExternalFilesDir 对比，风险同源，一并加固）。

### P1-4 全局明文流量放行，无 network_security_config
- 位置：`AndroidManifest.xml:20` `android:usesCleartextTraffic="true"`
- 影响：yt-dlp 提取的 http 渐进直链确实需要明文，但目前是**全局放行**：任何业务请求（含未来的订阅 URL、测速备用源）都可被降级为明文。
- 修复：`networkSecurityConfig` 白名单——默认 `cleartextTrafficPermitted="false"`，媒体 CDN 按需放行域。

### P1-5 Cookie 文件用后不删
- 位置：`YtDlp.kt:86-88` `writeCookies()` 写 `cacheDir/yt_cookies_*.txt`，任务完成后无清理
- 修复：`fallbackPlan` finally 中 `cookieFile?.delete()`。

### P2 安全卫生
- `TestWebViewActivity` `exported="true"`（Manifest:53-55）+ 自注释“测完删”：临时诊断页成为无意义攻击面，删。
- `ShareIn.resolveRedirect` / `Extractors.bskyProfile` cursor 拼接未编码（服务端值，配合明文流量可注入 query 参数）——低危。
- `CookieLoginActivity` 抓完 `removeAllCookies(null)` 清的是全 App WebView CookieStore（当前无其他 WebView 会话，行为正确但注意未来复用）。
- 大量 `catch (_: Exception) {}` 空吞无日志（`MainActivity:66` 等）——安全事件无从追溯。
- `Http.getJson`/`getText` 无响应体大小上限（`string()` 直接吃），异常响应可 OOM。

## 二、资深开发视角（并发 / 生命周期 / 数据一致性）

### P0-1 前缀误判导致删外部文件
见安全 P1-3——从数据破坏角度升级为 P0（删的是**别人 App 的用户文件**，不可逆）。

### P1-2 TaskManager 三张跨线程 HashMap
- 位置：`TaskManager.kt:25-26`（cancelFlags/fails）、`:461`（routeMemory）；`:152-162` cancel() 在 UI 线程写，2 个 IO worker 读
- 影响：取消指令可见性延迟（点了取消任务还在跑）、并发 put 丢 entry（routeMemory 失忆导致重复试错路由）。
- 修复：全部换 `ConcurrentHashMap`，一行成本。

### P1-3 收件箱查重三重缺陷 → 同 URL 双任务并发写同一 .part
- 位置：`TaskManager.kt:67`（内存 `listInbox().any` 查重）+ `Db.kt:803`（`listInbox` `LIMIT 300`）+ capture 无锁
- 影响：收件箱超 300 条后查重失效；剪贴板捕获与分享捕获并发时竞态 → 同 URL 两条任务 → 2 worker 并发下载同 dest（`TaskManager.kt:422` `.part` 固定命名）→ 文件互踩损坏、DB 靠 (post,index) 唯一约束兜底但文件已坏。
- 修复：① 查重下沉 `SELECT 1 FROM inbox WHERE url=?`；② `.part` 命名带 taskId；③ downloadPost 对同 dest 加 per-path 互斥。

### P1-4 DownloadService 每次启动泄漏一个 collector
- 位置：`DownloadService.kt:31-49`——每次 `onStartCommand` 都 `scope.launch { tasks.collectLatest }`，旧 collector 不取消；`lastUpdate` 节流变量跨 collector 竞争。
- 修复：`started` AtomicBoolean 守卫，或把收集移到 onCreate。

### P1-5 RootIO su 超时 10 分钟
- 位置：`RootIO.kt:25` `SU_TIMEOUT_MS = 10 * 60_000L`
- 影响：`RootProxy.probe()` 缓存 suAvailable=true 后授权被撤销/弹窗无人应答 → `syncExternalDir` 的 exec 阻塞 10 分钟（isCancelled 救不了阻塞中的 exec）。
- 修复：文件通道超时降到 30-60s，长任务分批（md5Batch 已分批，listTree 也应分目录）。

### P2 资深卫生项
- `Db.kt:482` mediaCols 与 `:725` `_MEDIA_SELECT_DELETED` 两处手写 23 列下标——加列错位即静默串列。收敛为单一 SQL 片段。
- `upsertAuthor/upsertPost/addMedia` 无事务包裹，进程死产生孤儿行（无害但统计脏）。低优先。
- `ContentAccess.ro_share` 缓存 key=路径 md5，不感知内容变化（属主同路径更新后最长 7 天播旧内容）——key 加 size+mtime。
- `residueSweep` 10 分钟 mtime 保护：极端慢速下载（>10min 无字节写入）会误删 .part。加“活跃任务 dest 集合”排除更稳。

## 三、新手视角（会真实踩到的坑）

### P1-1 destFile 时间戳未清洗（nowIso 分支）
- 位置：`TaskManager.kt:407-415`
  ```kotlin
  val stamp = post.createdAt.removeSuffix("Z").replace("-","")...ifBlank { nowIso() }
  ```
  `ifBlank` 兜底的 `nowIso()` 返回 `2026-09-11T11:21:23Z`——**含冒号，且不再经过 replace**。yt-dlp 通道拿不到 timestamp 时（entry.timestamp 缺失返回空串）必触发。
- 影响：Android 本地能建文件；一旦 MTP 拷到 Windows / 部分云盘同步 → 非法文件名报错。用户感知：“下载了但拷不出来”。
- 修复：stamp 整体走一次 sanitize（与 safeHandle 同款 Regex）。

### P1-2 shortcodeToId 静默错算
- 位置：`Extractors.kt:306-311` `alphabet.indexOf(ch).coerceAtLeast(0)` —— 非法字符当 0 处理
- 影响：算出错误 media id → IG 404 → 报错文案“Cookies 可能过期”，误导用户去重登。修复：非法字符直接 `return ""` 上抛明确错误。

### P2 新手卫生项
- `DownloadService.setProgress(100, 0, true)` indeterminate——通知文本有数字、进度条却永远转圈，两相矛盾。
- `Extractors.detect` scheme 大小写敏感（`removePrefix("https://")`）→ `HTTPS://X.COM/...` 识别失败。`.lowercase()` 预处理一次。
- 全代码 `catch (_: Exception) {}` 多处不留痕——至少 `Log.w(TAG, "...", e)`，否则线上问题不可复盘。

## 四、应用 Tracker 视角（对外行为审计）

### P0-1 默认配置下后台测速流量失控
- 位置：`ProxyManager.kt:296-325` optimizeLoop（`intervalMin` 默认 10 分钟全量复测）+ `Background.kt:26-33` WorkManager 15 分钟兜底 + `Store.kt:126-128` `autoOptimize` 默认 **true**
- 计算：每次全量检测 = N×204 小探测 + 每个**存活**候选 3s 吞吐下载（10Mbps ≈ 3.7MB）。5 个候选 ≈ 19MB/次 → 每 10 分钟 → **约 2.7GB/天**（Wi-Fi 下无感，移动数据下灾难）；且无 `TRANSPORT_CELLULAR/计费网络` 判断。
- 附带：测速源 Cloudflare（https）+ **Cachefly 明文 http**（`Store.kt:281`）——运营商侧可常态观测到 `10mb.test` 明文大流量特征。
- 修复：① 计费网络跳过吞吐测试（`NetworkCapabilities.NET_CAPABILITY_NOT_METERED`）；② 默认 interval 提到 30-60min；③ 备用测速源换 https。

### P1-2 平台指纹：冒充官方客户端的固定特征
- 位置：`Extractors.kt:293-294` IG_UA 固定 `Instagram 275.0.0.27.98 Android (...SM-G991B...)` + X-IG-App-ID
- 影响：同一 sessionid 背后是**非官方请求模式**（无签名头 X-IG-Capabilities/Signature、固定 UA、代理出口 IP 多变）→ 平台风控命中即 **sessionid 封禁乃至账号受限**。这是用户真实风险而非 App bug，但应在设置页明确告知“实验性、有封号风险”。

### P1-3 第三方可见你的兴趣画像
- X 元数据全走 `api.fxtwitter.com`（第三方公益服务）——它能看到你请求的每条推文/每个 handle（IP+UA 维度）。
- 本地 DB（authors/posts.text/media 全量）+ `allowBackup=true`（见安全 P0-2）→ 云端备份可完整还原兴趣画像。与安全 P0-2 同修。

### 清洁项（加分）
- **零第三方 SDK**：无广告、无统计、无崩溃上报、无设备指纹采集——tracker 视角本 App 是干净的。
- 剪贴板读取有前置过滤（先 `Extractors.detect` 命中才入库，Android 12+ 有系统粘贴提示），克制。
- proxy 认证信息不进日志（`ProxyCand.label()`、`ProxyUrl.display()` 均排除凭据）。
- SQL 全参数化（IN 拼接处均为 Long 列表，无注入面）；LIKE 通配符有 `likeEscape`。
